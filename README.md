# Агент перевірки робіт у Google Classroom

Агент за розкладом збирає здані самостійні та практичні роботи з Google Classroom,
пропонує оцінку за рубрикою з положення коледжу, оцінює ризик використання ШІ і веде
звіт у Google Sheets. **Остаточні рішення ухвалює викладач**: агент нічого не повертає
студентам і не виставляє остаточних оцінок.

> **Стан:** етап 1 (dry-run). Агент лише пише звіт у Sheets, у Classroom нічого не
> змінює. Запис чернеток оцінок у Classroom і розклад вмикаються на етапі 2 після
> перевірки результатів викладачем.

## Як це працює

```
review.py fetch   →  work/<запуск>/packets/*.json   (тексти робіт, без ПІБ)
claude -p         →  work/<запуск>/results/*.json   (бали за критеріями, ризик ШІ)
review.py apply   →  Google Sheets + exports/<запуск>.csv + state.json
```

- Доступ до Google мають лише скрипти. Модель (Claude Code у режимі `claude -p` з
  інструкціями `AGENT.md`) лише читає роботи й пише оцінки у файли.
- Студенти для моделі позначені псевдонімами, ПІБ потрапляють лише у звіт.
- Суму балів і оцінку рахує скрипт за шкалою з рубрики, а не модель.
- `state.json` пам'ятає оброблені роботи (id + час здачі + хеш вмісту), тому повторний
  запуск нічого не дублює. Якщо студент здав роботу знову зі зміненим вмістом, її буде
  перевірено ще раз, і у звіті з'явиться новий рядок.

## Встановлення

Потрібні Python 3.11+ і [Claude Code](https://docs.claude.com/en/docs/claude-code)
(команда `claude`, у якій ви вже увійшли у свій акаунт).

```bash
git clone https://github.com/olehmysiura/clasrum.git
cd clasrum
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium          # знадобиться на етапі 2
```

## Авторизація в Google

1. Покладіть файл OAuth client (Desktop app) у корінь проєкту під назвою
   `credentials.json`.
2. Виконайте `python auth.py`. Відкриється браузер: увійдіть під акаунтом викладача
   і дозвольте доступ. З'явиться `token.json`.
   - Якщо браузер на іншому комп'ютері, скористайтеся `python auth.py --manual`.
3. У Google Cloud мають бути ввімкнені **Classroom API, Drive API і Google Sheets API**.
   Якщо Sheets API не ввімкнено, скрипт покаже посилання, де його ввімкнути.

`credentials.json`, `token.json`, `state.json`, `config.yaml`, `browser_profile/`,
а також теки з текстами робіт (`work/`, `history/`, `exports/`, `logs/`) додано в
`.gitignore`. Не публікуйте їх.

## Налаштування `config.yaml`

```bash
cp config.example.yaml config.yaml
python review.py courses       # назви курсів і груп, як у Classroom
python review.py assignments   # назви завдань у курсах з config.yaml
```

Для кожного курсу вкажіть рубрику і завдання з видом роботи (`практична`, `семінарська`,
`самостійна`, `реферат`, `презентація`, `доповідь`, `контрольна`). `spreadsheet_id`
залиште порожнім: під час першого запуску скрипт створить таблицю «Звіт перевірки
робіт 2026/2027» і сам впише її id. `max_submissions_per_run` обмежує обсяг одного
запуску.

## Рубрики (`criteria/`)

- `criteria/polozhennia-kryterii-otsiniuvannia-2025.pdf` — положення коледжу
  (у git не потрапляє).
- `criteria/<дисципліна>.md` — рубрика: шкала переведення, розділи
  `## Вид роботи: …` з таблицею критеріїв і балів, типові помилки, доповнення
  викладача. Сума балів кожного виду роботи має дорівнювати 100.

Положення задає критерії, але не задає ваги, тому в `трудове-право.md` критерії мають
рівну вагу (по 25). Змініть колонку «Макс. бали», якщо ваги мають бути іншими. Для
інших дисциплін скопіюйте файл і допишіть розділ «Доповнення викладача».

## Запуск

Вручну:

```bash
./run_review.sh                                            # macOS / Linux
powershell -ExecutionPolicy Bypass -File .\run_review.ps1  # Windows
```

Можна й поетапно: `python review.py fetch`, потім `claude -p "Виконай інструкції з
AGENT.md. Тека запуску: work/<запуск>"`, потім `python review.py apply --run work/<запуск>`.

Журнали зберігаються в `logs/`.

### За розкладом (вмикається на етапі 2)

**macOS / Linux:** `crontab -e` і рядок (щодня о 20:00):

```
0 20 * * * /ПОВНИЙ/ШЛЯХ/до/clasrum/run_review.sh
```

На macOS дайте `cron` доступ до диска (Системні параметри → Конфіденційність і безпека
→ Повний доступ до диска → `/usr/sbin/cron`). Комп'ютер о 20:00 має бути увімкнений.

**Windows:** Планувальник завдань:

```powershell
schtasks /Create /TN "Перевірка робіт Classroom" /SC DAILY /ST 20:00 ^
  /TR "powershell -ExecutionPolicy Bypass -File C:\ШЛЯХ\до\clasrum\run_review.ps1"
```

## Звіт у Google Sheets

- Кожна група або курс має окремий аркуш. Колонки: ПІБ студента, завдання, час здачі,
  статус (вчасно або із запізненням), запропонована оцінка, бали, розбивка за
  критеріями, зауваження, ризик ШІ, примітка щодо ШІ, уточнювальні запитання, статус
  чернетки в Classroom, дата перевірки, посилання, **Рішення викладача** (для ручного
  заповнення) і прихований службовий ключ.
- Нові рядки лише додаються в кінець. Ваші правки в наявних рядках скрипт не чіпає.
- Рядки із середнім ризиком ШІ підсвічуються жовтим, із високим — червоним.
- Аркуш «Підсумок» перераховується під час кожного запуску.
- Якщо роботу не вдалося прочитати, у звіті вказано причину: «файл недоступний»,
  «порожній» або «непідтримуваний формат».

## Ризик ШІ

Це сигнал для викладача, а не доказ. Він не впливає на оцінку і не потрапляє в
коментар, який бачить студент. Для робіт із середнім або високим ризиком агент
пропонує 2–3 уточнювальні запитання.
